문제 해결 사례전부 실제 커밋 근거

공무링크 · 2026.09
가불금 5만원을 뺐는데 실제로는 10만원이 빠졌다
상황
노무관리에 가불금 같은 "기타공제" 항목을 새로 추가했는데, 배포 후 특정 케이스(국민연금 임의가입 처리)에서 공제액이 두 배로 깎여 저장되는 문제가 나왔습니다.
원인
이 시스템은 급여 확정 경로가 두 갈래였습니다. 하나는 최종 금액을 통째로 계산해 저장하는 절대값 경로, 다른 하나는 "기존 금액에서 얼마를 뺀다"는 상대 감산 경로. 기타공제 기능을 추가하면서 두 경로가 공유하는 SQL에 "공제액을 무조건 한 번 뺀다"를 넣었는데, 상대 감산 경로는 이미 그 공제가 반영된 값을 넘기고 있어서 같은 금액이 한 번 더 빠졌습니다.
해결
SQL에서 두 경로를 억지로 맞추는 대신, 절대값을 만드는 계산 함수 쪽에서 공제액을 직접 계산하도록 구조를 바꿨습니다. 각 경로가 자기 책임 범위 안에서 계산을 끝내도록 분리한 것입니다.
검증
타입 체크·린트·E2E 테스트(225건) 결과가 그대로 유지되는 걸 확인 후 반영했습니다.

공무링크 · 2026.09
다른 대행기관 현장 이름이 화면에 떴다
상황
"이 근로자는 이미 다른 현장에 근무 기록이 있다"고 걸러주는 중복근로일 검사 기능이, 문제없는 근로자를 걸러내고 낯선 현장 이름까지 화면에 노출한다는 제보가 있었습니다.
원인
저희 DB는 하나의 스키마 안에 여러 대행기관의 사업장 데이터가 함께 들어 있습니다. 근로자 식별번호(SABUN)는 대행기관과 무관하게 시스템 전체에서 공통으로 씁니다. 문제의 조회 함수는 이 번호만으로 근무 기록을 찾고 있어서, 다른 대행기관이 관리하는 현장의 기록까지 같이 걸려 나온 것이었습니다 — 대행기관 경계가 없는 조회였습니다.
해결
조회 범위를 대행기관 코드(BONSA_CODE)로 좁혔습니다. 저장 로직은 그대로 두고 "무엇을 찾아올지"의 범위만 좁혀서, 정상 케이스에는 영향이 없었습니다.
검증
운영 데이터 300건을 표본으로 수정 전/후를 직접 대조했고, "이 조건을 빼면 반드시 실패한다"는 것까지 확인하는 재발 방지 테스트 3건을 추가했습니다.

현장링크 · 2026.07
로그인 없이도 남의 체크리스트를 건드릴 수 있었다
상황
현장 근로자용 앱의 체크리스트 저장·조회 API를 점검하다가, 로그인 여부를 확인하지 않는 엔드포인트 몇 개를 발견했습니다.
원인
기능 구현을 먼저 끝내는 데 집중하다 보니 일부 API에 로그인 가드가 빠져 있었고, 요청 값만 바꾸면 자기 배정 건이 아닌 것도 처리되는 경로(IDOR)가 있었습니다. 사진을 여러 장 찍으면 같은 파일명으로 저장돼 이전 사진을 덮어쓰는 문제도 함께 있었습니다.
해결
로그인 가드와 배정 건 소유권 검증을 추가하고, 사진 파일명에 항목 번호를 넣어 덮어쓰기를 막았습니다. 제출이 서버 응답 전에 끊기면 다음 태깅 때 재제출되도록 흐름도 같이 고쳤습니다.
검증
정상 사용자 플로우(출퇴근 태깅, 체크리스트 제출)가 그대로 동작하는 것을 확인.

건설HR · 2026.06 · 단독
0에서 시작하며 가장 먼저 걸러낸 건 내 실수였다
상황
신규 서비스를 0부터 만들면서, 초기 며칠은 개발 속도를 위해 DB 접속 정보를 코드 파일에 바로 넣어뒀습니다.
해결
배포 전 자체 점검 과정에서 바로 인지하고, 환경변수(.env) 기반으로 옮기고 .env.example을 남겼습니다.
왜 적어두는가
완벽하게 시작하지 못했다는 걸 감추기보다, 0에서 시작할 때 실제로 어떤 순서로 정리해나가는지를 그대로 보여주는 게 더 정직하다고 생각해 남깁니다.

ddalkkak (개인 프로젝트) · 2026.09
내가 만든 퍼즐인데 답이 하나가 아니었다
상황
직접 만든 두뇌 퍼즐 게임의 발견형 문제 181개를 전수 재검수하는 작업에서, "의도한 것과 다른 답도 가능한" 문제 19건을 찾아냈습니다.
예시 1 — 그림이 물리 법칙과 반대였다
시소 문제 하나는 그림이 라벨과 반대로 그려져 있었습니다. 널빤지와 추의 좌표를 직접 계산해 모멘트를 검산해보니(왼쪽 24 : 오른쪽 12) 왼쪽이 내려가야 하는데, 그림은 오른쪽이 내려간 모습이었습니다. 좌표를 다시 잡아 그림과 정답을 일치시켰습니다.
예시 2 — 규칙이 우연히 두 개였다
받침 유무로 회원을 가르는 문제에서, 예시로 든 단어들이 우연히 "고유어인지"로도 똑같이 갈렸습니다. 의도한 규칙이 아닌 쪽으로도 답이 나올 수 있었던 것이라, 두 규칙이 서로 다른 답을 내는 반례 단어를 추가해서 막았습니다.
원칙
정답은 하나도 바꾸지 않고, "이 문제가 유일한 답을 갖는가"만 별도로 검증하는 체계를 만들어 계속 운영하고 있습니다.
